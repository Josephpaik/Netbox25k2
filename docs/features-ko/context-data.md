# 컨텍스트 데이터

구성 컨텍스트 데이터(줄여서 "컨피그 컨텍스트")는 특정 특성을 기반으로 장비와 가상 머신에 적용되는 임의의 데이터를 사용자가 정의할 수 있게 하는 강력한 기능입니다. 예를 들어 특정 지역 내의 사이트에 할당된 장비에 대해 syslog 서버를 정의하고 싶다고 가정합니다. NetBox에서 이 데이터를 포함하는 구성 컨텍스트 인스턴스를 만들고 원하는 지역에 적용할 수 있습니다. 이제 이 지역 내의 모든 장비는 API를 통해 가져올 때 이 데이터를 포함합니다.

```json
{
    "syslog-servers": [
        "192.168.43.107",
        "192.168.48.112"
    ]
}
```

컨텍스트 데이터는 원격 API 클라이언트가 사용하거나 [구성 템플릿](./configuration-rendering.md)을 렌더링하는 데 기본적으로 사용될 수 있습니다.

다음 기준에 따라 객체에 대한 구성 컨텍스트를 계산할 수 있습니다:

| 유형 | 장비 | 가상 머신 |
|------|------|-----------|
| 지역 | :material-check: | :material-check: |
| 사이트 그룹 | :material-check: | :material-check: |
| 사이트 | :material-check: | :material-check: |
| 위치 | :material-check: | |
| 장비 유형 | :material-check: | |
| 역할 | :material-check: | :material-check: |
| 플랫폼 | :material-check: | :material-check: |
| 클러스터 유형 | | :material-check: |
| 클러스터 그룹 | | :material-check: |
| 클러스터 | | :material-check: |
| 테넌트 그룹 | :material-check: | :material-check: |
| 테넌트 | :material-check: | :material-check: |
| 태그 | :material-check: | :material-check: |

구성 컨텍스트에 저장할 수 있는 데이터에는 JSON으로 표현할 수 있는 한 제한이 없습니다.

## 계층적 렌더링

이것 자체로도 유용하지만, 컨텍스트 데이터의 진정한 힘은 여러 인스턴스를 사용하여 병합하고 재정의할 수 있는 능력에서 비롯됩니다. 예를 들어 특정 장비 역할에 대해 지역 내에서 _다른_ syslog 서버를 정의해야 할 수 있습니다. 적절한 데이터와 더 높은 가중치를 가진 두 번째 구성 컨텍스트를 만들고 원하는 역할에 적용할 수 있습니다. 이렇게 하면 전체 지역에 적용되는 낮은 가중치 데이터가 재정의됩니다. 상상할 수 있듯이 이 유연성은 많은 복잡한 사용 사례에 대응할 수 있습니다.

예를 들어 지역 내의 모든 장비에 대해 syslog 및 NTP 서버 세트를 지정하고 싶다고 가정합니다. 다음 JSON 데이터와 함께 지역에 할당된 가중치 1000의 구성 컨텍스트 인스턴스를 만들 수 있습니다:

```json
{
    "ntp-servers": [
        "172.16.10.22",
        "172.16.10.33"
    ],
    "syslog-servers": [
        "172.16.9.100",
        "172.16.9.101"
    ]
}
```

하지만 이 지역 내의 특정 사이트에 지역 syslog 서버에 도달하지 못하게 하는 문제가 있다고 가정합니다. 해당 장비는 위에서 정의한 두 개 대신 로컬 syslog 서버를 사용해야 합니다. 해당 사이트에만 할당되고 가중치가 2000인 다음 데이터를 가진 두 번째 구성 컨텍스트를 만들겠습니다:

```json
{
    "syslog-servers": [
        "192.168.43.107"
    ]
}
```

이 사이트에 있는 장비의 컨텍스트 데이터가 렌더링되면 두 번째 더 높은 가중치의 데이터가 첫 번째를 덮어쓰고 다음과 같이 됩니다:

```json
{
    "ntp-servers": [
        "172.16.10.22",
        "172.16.10.33"
    ],
    "syslog-servers": [
        "192.168.43.107"
    ]
}
```

높은 가중치 컨텍스트의 데이터가 낮은 가중치 컨텍스트의 충돌하는 데이터를 덮어쓰고, 낮은 가중치 컨텍스트의 충돌하지 않는 부분(NTP 서버 목록)은 보존됩니다.

## 로컬 컨텍스트 데이터

장비와 가상 머신에도 로컬 컨텍스트 데이터를 정의할 수 있습니다. 이 로컬 컨텍스트는 장비/VM에 적용되는 별도의 구성 컨텍스트 객체보다 _항상_ 우선합니다. 이는 특정 객체에 대한 데이터에서 특정 편차를 호출해야 하는 상황에서 유용합니다.

!!! warning
    많은 개별 장비 또는 가상 머신에 대해 일상적으로 로컬 컨텍스트 데이터를 정의하고 있다면 [사용자 정의 필드](./customization.md#custom-fields)가 더 효과적인 솔루션을 제공할 수 있습니다.
