# 이벤트 규칙

NetBox에는 내부 이벤트에 대응하여 특정 기능을 자동으로 수행하는 기능이 포함되어 있습니다. 여기에는 다음이 포함됩니다:

* [사용자 정의 스크립트](../customization/custom-scripts.md) 실행
* [웹훅](../integrations/webhooks.md) 전송
* [사용자 알림](../features/notifications.md) 생성

예를 들어 장비의 운영 상태가 active로 변경되면 모니터링 시스템이 해당 장비를 자동으로 모니터링하기 시작하고, 다른 상태의 경우 모니터링에서 제거하도록 구성하고 싶다고 가정합니다. NetBox에서 장비 모델에 대한 웹훅을 만들고 수신 시스템에서 원하는 변경을 실행하기 위한 콘텐츠와 대상 URL을 작성할 수 있습니다. 그런 다음 이 웹훅과 이벤트 규칙을 연결하면 구성된 제약 조건이 충족될 때마다 NetBox가 자동으로 웹훅을 보냅니다.

각 이벤트는 하나 이상의 NetBox 객체 유형과 하나 이상의 이벤트(예: 생성, 업데이트 또는 삭제)에 연결되어야 합니다.

## 조건부 이벤트 규칙

이벤트 규칙에는 특정 객체에 대해 이벤트가 트리거되는지 여부를 제어하는 데 사용되는 JSON으로 표현된 조건부 논리 집합이 포함될 수 있습니다. 예를 들어 객체의 `status` 필드가 "active"인 경우에만 장비에 대한 이벤트를 트리거하고 싶을 수 있습니다:

```json
{
  "and": [
    {
      "attr": "status.value",
      "value": "active"
    }
  ]
}
```

자세한 내용은 NetBox의 [조건부 논리](../reference/conditions.md)에 대한 참조 문서를 확인하세요.

## 이벤트 규칙 처리

변경이 감지되면 결과 이벤트는 처리를 위해 Redis 대기열에 배치됩니다. 이렇게 하면 발신 이벤트가 처리될 때까지 기다릴 필요 없이 사용자의 요청이 완료됩니다. 그런 다음 이벤트는 `rqworker` 프로세스에 의해 대기열에서 추출됩니다. 현재 이벤트 대기열과 실패한 이벤트는 System > Background Tasks에서 검사할 수 있습니다.
