# 커스터마이징

NetBox는 모든 네트워크의 요구를 충족시키기 위해 노력하지만, 사용자가 자신의 고유한 환경에 맞게 조정해야 하는 필요성을 무시할 수 없습니다. NetBox는 이를 염두에 두고 구축되었으며 특정 요구 사항에 더 잘 맞도록 다양한 방법으로 사용자 정의할 수 있습니다.

최종 사용자 개인화 주제(북마크, 테이블 기본 설정, 언어, CSV 구분 기호 등)는 [기능 > 사용자 기본 설정](../features/user-preferences.md)을 참조하세요.

## 태그

NetBox의 대부분의 객체에는 조직화 및 필터링을 돕기 위해 사용자가 만든 태그를 할당할 수 있습니다. 태그 값은 완전히 임의적입니다: 키-값 쌍으로 데이터를 저장하는 데 사용하거나 객체를 필터링할 수 있는 레이블로만 사용할 수 있습니다. 각 태그에는 사용자 인터페이스에서 더 빠른 구분을 위해 색상을 할당할 수도 있습니다.

객체는 적용된 태그로 필터링할 수 있습니다. 예를 들어 다음 API 요청은 "monitored"로 태그된 모든 장비를 검색합니다:

```no-highlight
GET /api/dcim/devices/?tag=monitored
```

`tag` 필터는 _모든_ 지정된 태그가 할당된 객체만 일치시키기 위해 여러 번 지정할 수 있습니다:

```no-highlight
GET /api/dcim/devices/?tag=monitored&tag=deprecated
```

## 사용자 정의 필드

NetBox는 기본적으로 상당히 광범위한 데이터 모델을 제공하지만, NetBox 객체와 관련된 특정 추가 데이터를 저장해야 할 필요가 발생할 수 있습니다. 예를 들어 설치된 장비와 함께 송장 ID를 기록하거나 새 IP 프리픽스를 생성할 때 승인 권한자를 기록해야 할 수 있습니다. NetBox 관리자는 이러한 요구를 충족하기 위해 기본 제공 객체에 사용자 정의 필드를 만들 수 있습니다.

NetBox는 문자열과 정수와 같은 기본 데이터 유형부터 선택 목록이나 원시 JSON과 같은 복잡한 구조까지 많은 유형의 사용자 정의 필드를 지원합니다. 다른 NetBox 객체를 참조하는 사용자 정의 필드를 추가하는 것도 가능합니다. 사용자 정의 필드 데이터는 적용된 객체와 함께 데이터베이스에 직접 저장되어 최소한의 성능 영향을 보장합니다. 그리고 사용자 정의 필드 데이터는 기본 제공 필드와 마찬가지로 REST API를 통해 쓰고 읽을 수 있습니다.

이 기능에 대해 자세히 알아보려면 [사용자 정의 필드 문서](../customization/custom-fields.md)를 확인하세요.

## 사용자 정의 링크

사용자 정의 링크를 사용하면 NetBox UI 내에서 NetBox 객체와 관련된 외부 리소스를 편리하게 참조할 수 있습니다. 예를 들어 NetBox에서 모델링된 각 가상 머신을 일부 오케스트레이션 애플리케이션의 해당 뷰에 연결하고 싶을 수 있습니다. 가상 머신 모델에 대한 템플릿화된 사용자 정의 링크를 만들고 링크 URL에 다음과 같이 지정하여 이를 수행할 수 있습니다:

```no-highlight
http://server.local/vms/?name={{ object.name }}
```

이제 NetBox에서 가상 머신을 볼 때 사용자는 선택한 제목과 링크(보고 있는 VM의 이름이 포함된)가 있는 편리한 버튼을 볼 수 있습니다. 사용자 정의 링크의 텍스트와 URL 모두 이 방식으로 템플릿화할 수 있으며, 더 효율적인 표시를 위해 사용자 정의 링크를 드롭다운으로 함께 그룹화할 수 있습니다.

이 기능에 대해 자세히 알아보려면 [사용자 정의 링크 문서](../customization/custom-links.md)를 확인하세요.

## 사용자 정의 유효성 검사

NetBox는 데이터베이스의 무결성을 보장하기 위해 강력한 기본 제공 객체 유효성 검사를 사용하지만, 특정 객체의 생성 및 수정을 관리하는 추가 규칙을 적용하고 싶을 수 있습니다. 예를 들어 NetBox에 정의된 모든 장비가 특정 명명 체계를 준수하고 자산 태그를 포함해야 할 수 있습니다. 장비 모델에 대해 이러한 요구 사항을 적용하도록 NetBox에서 사용자 정의 유효성 검사 규칙을 구성할 수 있습니다:

```python
CUSTOM_VALIDATORS = {
    "dcim.device": [
        {
            "name": {
                "regex": "[a-z]+\d{3}"
            },
            "asset_tag": {
                "required": True
            }
        }
    ]
}
```

이 기능에 대해 자세히 알아보려면 [사용자 정의 유효성 검사 문서](../customization/custom-validation.md)를 확인하세요.

## 내보내기 템플릿

대부분의 NetBox 객체는 현재 뷰(사용자가 현재 객체 목록에서 보는 것) 또는 모든 사용 가능한 데이터의 두 가지 기본 제공 CSV 형식으로 대량 내보낼 수 있습니다. NetBox는 또한 내보내기 템플릿을 통해 고유한 사용자 정의 데이터 내보내기 형식을 정의하는 기능을 제공합니다. 내보내기 템플릿은 본질적으로 특정 객체 유형과 연결된 [Jinja2](https://jinja.palletsprojects.com/) 템플릿 코드입니다. NetBox UI의 객체 목록에서 사용자는 생성된 내보내기 템플릿 중 하나를 선택하여 템플릿 로직에 따라 객체를 내보낼 수 있습니다.

내보내기 템플릿이 CSV 데이터를 렌더링할 필요는 없습니다: 출력은 모든 문자 기반 형식일 수 있습니다. 예를 들어 탭을 구분 기호로 사용하여 데이터를 렌더링하거나 IP 주소 목록에서 직접 DNS 주소 레코드를 만들 수도 있습니다. 내보내기 템플릿은 필요한 형식으로 필요한 데이터를 빠르게 얻을 수 있는 좋은 방법입니다.

이 기능에 대해 자세히 알아보려면 [내보내기 템플릿 문서](../customization/export-templates.md)를 확인하세요.

## 보고서

NetBox 관리자는 NetBox 내에서 실행되고 NetBox UI 내에서 실행 및 분석할 수 있는 _보고서_로 알려진 사용자 정의 Python 스크립트를 설치할 수 있습니다. 보고서는 임의의 규칙 집합에 대해 NetBox 객체를 평가하는 좋은 방법입니다. 예를 들어 모든 라우터에 IP 주소가 할당된 루프백 인터페이스가 있는지 또는 모든 사이트에 최소한의 VLAN 집합이 정의되어 있는지 확인하는 보고서를 작성할 수 있습니다.

보고서가 실행되면 수행 중인 작업과 관련된 메시지를 로깅하고 궁극적으로 통과 또는 실패로 결과를 냅니다. 보고서는 UI, REST API 또는 CLI(관리 명령으로)를 통해 실행할 수 있습니다. 즉시 실행하거나 미래의 시간에 실행하도록 예약할 수 있습니다.

이 기능에 대해 자세히 알아보려면 [보고서 문서](../customization/reports.md)를 확인하세요.

## 사용자 정의 스크립트

사용자 정의 스크립트는 보고서와 유사하지만 더 강력합니다. 사용자 정의 스크립트는 양식(또는 API 데이터)을 통해 사용자에게 입력을 요청할 수 있으며 보고서 이상의 많은 작업을 수행하도록 구축되었습니다. 사용자 정의 스크립트는 일반적으로 NetBox의 새 객체 채우기 또는 외부 시스템과의 데이터 교환과 같은 작업을 자동화하는 데 사용됩니다. 보고서와 마찬가지로 UI, REST API 또는 CLI를 통해 실행할 수 있으며 미래의 시간에 실행하도록 예약할 수 있습니다.

전체 Python 환경은 NetBox의 모든 내부 메커니즘을 포함하여 사용자 정의 스크립트에서 사용할 수 있습니다: 스크립트가 할 수 있는 것에 대한 인위적인 제한이 없습니다. 따라서 사용자 정의 스크립팅은 고급 기능으로 간주되며 Python과 NetBox의 데이터 모델에 대한 충분한 숙지가 필요합니다.

이 기능에 대해 자세히 알아보려면 [사용자 정의 스크립트 문서](../customization/custom-scripts.md)를 확인하세요.
