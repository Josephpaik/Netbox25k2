# 객체 기반 권한

NetBox는 Django의 기본 권한 모델을 대체하는 새로운 객체 기반 권한 프레임워크를 사용합니다. 객체 기반 권한을 통해 관리자는 특정 유형의 모든 객체가 아닌 NetBox의 임의 객체 하위 집합에 대해 작업을 수행할 수 있는 권한을 사용자 또는 그룹에 부여할 수 있습니다. 예를 들어 사용자에게 특정 지역 내의 사이트만 볼 수 있는 권한을 부여하거나 특정 범위 내의 숫자 ID를 가진 VLAN만 수정할 수 있는 권한을 부여할 수 있습니다.

NetBox의 권한은 여러 구성 요소 간의 관계를 나타냅니다:

* 객체 유형 - NetBox의 하나 이상의 객체 유형
* 사용자/그룹 - 하나 이상의 사용자 또는 사용자 그룹
* 작업 - 객체에 대해 수행할 수 있는 작업
* 제약 조건 - 부여된 작업을 특정 객체 하위 집합으로 제한하는 데 사용되는 임의 필터

최소한 권한 할당은 하나의 객체 유형, 하나의 사용자 또는 그룹, 하나의 작업을 지정해야 합니다. 제약 조건 지정은 선택 사항입니다: 제약 조건이 지정되지 않은 권한은 선택한 모델의 모든 인스턴스에 적용됩니다.

## 작업

NetBox 내의 각 객체 유형에 대해 허용할 수 있는 네 가지 핵심 작업이 있으며, 이는 CRUD 규칙(생성, 읽기, 업데이트, 삭제)과 대략 유사합니다:

* **View** - 데이터베이스에서 객체 검색
* **Add** - 새 객체 생성
* **Change** - 기존 객체 수정
* **Delete** - 기존 객체 삭제

이 외에도 권한은 특정 모델이나 플러그인에서 필요로 하는 사용자 정의 작업을 부여할 수도 있습니다. 예를 들어 스크립트에 대한 `run` 권한은 사용자가 사용자 정의 스크립트를 실행할 수 있게 합니다. 이러한 작업은 권한을 부여할 때 "추가 작업" 필드에서 지정할 수 있습니다.

!!! note
    내부적으로 권한에 의해 부여된 모든 작업(기본 제공 및 사용자 정의 모두)은 `actions`라는 배열 필드에 문자열로 저장됩니다.

## 제약 조건

제약 조건은 [Django 쿼리 필터](https://docs.djangoproject.com/en/stable/ref/models/querysets/#field-lookups)를 나타내는 JSON 객체 또는 목록으로 표현됩니다. 이는 Django ORM을 사용하여 쿼리를 수행할 때 QuerySet `filter()` 메서드에 전달하는 것과 동일한 구문입니다. 쿼리 필터와 마찬가지로 이중 밑줄을 사용하여 관련 객체를 탐색하거나 조회 표현식을 호출할 수 있습니다. 몇 가지 예제 쿼리와 해당 정의가 아래에 나와 있습니다.

단일 JSON 객체 내에 정의된 모든 속성은 논리적 AND로 적용됩니다. 예를 들어 다음 제약 조건으로 site 모델에 대한 권한을 할당한다고 가정합니다.

```json
{
  "status": "active",
  "region__name": "Americas"
}
```

이 권한은 "active" 상태이**면서** "Americas" 지역에 할당된 사이트에만 접근 권한을 부여합니다.

다른 제약 조건 집합으로 논리적 OR을 달성하려면 목록 내에 여러 객체를 정의합니다. 예를 들어 ID가 100에서 199 사이인 VLAN _또는_ "reserved" 상태인 VLAN으로 권한을 제한하려면 다음과 같이 합니다:

```json
[
  {
    "vid__gte": 100,
    "vid__lt": 200
  },
  {
    "status": "reserved"
  }
]
```

또한 객체 유형에 대해 여러 권한이 할당된 경우 해당 집합 제약 조건은 논리적 "OR" 연산을 사용하여 병합됩니다.

### 사용자 토큰

권한 제약 조건을 정의할 때 관리자는 특수 토큰 `$user`를 사용하여 평가 시점의 현재 사용자를 참조할 수 있습니다. 이는 사용자가 자신의 저널 항목만 편집하도록 제한하는 데 유용할 수 있습니다. 이러한 제약 조건은 다음과 같이 정의할 수 있습니다:

```json
{
  "created_by": "$user"
}
```

`$user` 토큰은 제약 조건 값으로만 사용하거나 값 목록 내의 항목으로만 사용할 수 있습니다. 특정 사용자 속성을 참조하도록 수정하거나 확장할 수 없습니다.

### 기본 권한

권한은 일반적으로 특정 그룹 및/또는 사용자에게 할당되지만, _모든_ 인증된 사용자에게 적용되는 기본 권한 집합을 정의할 수도 있습니다. 이는 [`DEFAULT_PERMISSIONS`](../configuration/security.md#default_permissions) 구성 매개변수를 사용하여 수행됩니다. 특정 사용자 또는 그룹에 대한 권한을 정적으로 구성하는 것은 **지원되지 않습니다**.

### 제약 조건 정의 예제

| 제약 조건 | 설명 |
| ----------- | ----------- |
| `{"status": "active"}` | 상태가 active |
| `{"status__in": ["planned", "reserved"]}` | 상태가 active **또는** reserved |
| `{"status": "active", "role": "testing"}` | 상태가 active **이면서** 역할이 testing |
| `{"name__startswith": "Foo"}` | 이름이 "Foo"로 시작 (대소문자 구분) |
| `{"name__iendswith": "bar"}` | 이름이 "bar"로 끝남 (대소문자 구분 안 함) |
| `{"vid__gte": 100, "vid__lt": 200}` | VLAN ID가 100 이상 **이면서** 200 미만 |
| `[{"vid__lt": 200}, {"status": "reserved"}]` | VLAN ID가 200 미만 **또는** 상태가 reserved |

## 권한 적용

### 객체 보기

객체 기반 권한은 사용자 요청으로 생성된 데이터베이스 쿼리를 필터링하여 반환되는 객체 집합을 제한하는 방식으로 작동합니다. 요청이 수신되면 NetBox는 먼저 사용자가 인증되었는지와 요청된 작업을 수행할 권한이 부여되었는지 확인합니다. 예를 들어 요청된 URL이 `/dcim/devices/`인 경우 NetBox는 `dcim.view_device` 권한을 확인합니다. 사용자에게 이 권한이 할당되지 않은 경우(직접 또는 그룹 할당을 통해) NetBox는 403(금지됨) HTTP 응답을 반환합니다.

권한이 _부여된_ 경우 NetBox는 모델 및 작업에 대해 지정된 모든 제약 조건을 컴파일합니다. 예를 들어 다음 제약 조건으로 device 모델에 대한 보기 권한을 부여하는 두 개의 권한이 사용자에게 할당되었다고 가정합니다:

```json
[
    {"site__name__in":  ["NYC1", "NYC2"]},
    {"status":  "offline", "tenant__isnull":  true}
]
```

이는 사용자에게 NYC1 또는 NYC2라는 사이트에 할당된 장비, **또는** "offline" 상태이면서 테넌트가 할당되지 않은 장비를 볼 수 있는 권한을 부여합니다. 이러한 제약 조건은 다음 ORM 쿼리와 동일합니다:

```no-highlight
Site.objects.filter(
    Q(site__name__in=['NYC1', 'NYC2']),
    Q(status='active', tenant__isnull=True)
)
```

### 객체 생성 및 수정

사용자가 NetBox에서 객체를 생성하거나 수정하려고 할 때도 동일한 유형의 논리가 적용되지만, 약간의 변형이 있습니다. 유효성 검사가 완료되면 NetBox는 변경을 용이하게 하기 위해 원자적 데이터베이스 트랜잭션을 시작하고 객체는 정상적으로 생성되거나 저장됩니다. 그런 다음 트랜잭션 내에서 NetBox는 새로 생성/업데이트된 객체를 검색하기 위한 두 번째 쿼리를 발행하고 객체의 기본 키로 제한된 쿼리셋을 필터링합니다. 이 쿼리가 객체를 반환하지 못하면 NetBox는 새 수정본이 권한에 의해 부과된 제약 조건과 일치하지 않음을 알게 됩니다. 그런 다음 트랜잭션이 롤백되어 변경 전의 원래 상태로 데이터베이스가 남고 사용자에게 위반 사항이 알려집니다.
